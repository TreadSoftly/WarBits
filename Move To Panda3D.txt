The “Project Constitution” (rules we do not break)

These rules should be reflected in docs + tests and enforced by how we refactor:

Single unit system (SI internally)
All physics uses meters, seconds, kg, radians, Newtons. Any spreadsheet weirdness gets converted at ingestion.

Determinism is sacred
A scenario seed produces the same outcomes (within tiny floating tolerances). This is mandatory for debugging, realism validation, multiplayer sanity, and AI training.

Engine ≠ Renderer
The simulation must be able to run headless (no Matplotlib) for tests/training/CI. Rendering consumes state; it doesn’t own reality.

No silent physics failures
Returning empty arrays on exceptions is fine for a “demo never crashes” mode, but tests/dev mode must surface errors.

FPS is a feature
Everything gets a performance budget. Expensive features must have LOD/quality knobs and profiling coverage.

Yeah — there are a few extra things I’d add, but only the ones that are genuinely high-leverage and “real-world” (not fluff). Here’s what I think is missing or under-emphasized in the plan so far.

Data rights and “can we ship this?”

This isn’t about being paranoid; it’s about not getting kneecapped later.

Licensing / provenance policy for your datasets

If any numbers are derived from War Thunder game files, community dumps, screenshots, etc., you need to decide what you’re comfortable distributing publicly.

If you ever ship on Steam, this matters more.

Asset policy

Avoid bundling any copyrighted models/textures/sounds from other games.

Build toward an “open assets only” pipeline (or your own created assets), even if today it’s simple polygons.

Why it matters: you can build the best sim on Earth and still get blocked from distribution if the data/assets story isn’t clean.

Determinism across machines isn’t automatic

You already care about determinism (good), but one detail is easy to underestimate:

Floating point determinism differs across OS/CPU sometimes

Same seed ≠ bit-identical results forever.

What you want is: deterministic enough + tolerance-based tests + consistent RNG usage.

Concrete additions I’d make:

A documented “determinism target”:

Exact match for discrete decisions and event ordering.

Tolerance match for continuous physics (positions/velocities).

A hard rule: one RNG source for sim logic (numpy.random.Generator), passed explicitly, never “hidden global random”.

Why it matters: otherwise multiplayer, CI tests, and “replay a bug” becomes a horror movie.

Replays and forensic debugging (this will save your sanity)

Right now you have impacts/events lists, which is a good start. I’d add:

Replay file format (minimal, deterministic-first)

Record: seed, config hash, and player/AI inputs (or schedule decisions).

Optionally record checkpoints (state snapshots every N seconds) to fast-forward.
